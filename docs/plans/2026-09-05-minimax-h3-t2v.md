# MiniMax H3 文生视频 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 通过现有 Task Plugin 与视频 Playground，以最小改动接入新加坡 5090 上的 ComfyUI MiniMax H3 纯文生视频能力，并支持原生音频开关。

**Architecture:** 新增一个只声明 `openai_video` 协议的 `minimax-h3` Task Plugin，把现有 `/v1/videos` 请求转换为最小 ComfyUI API workflow，并通过任务轮询和内容代理返回生成视频。前端用模型能力函数为 `minimax-h3-fl2va` 限定 768p、五种比例、5–15 秒和纯文本输入，不修改 Seedance 行为，不新增数据库结构、依赖或核心 Go adapter。

**Tech Stack:** JavaScript Task Plugin API v1、Go 1.25 测试宿主、React 19、TypeScript、Zod、Vitest、React Testing Library、Rsbuild。

### Task 2: 用 TDD 实现请求校验与 ComfyUI workflow

**Files:**
- Create: `plugins/minimax_h3_test.go`
- Modify: `plugins/tasks/minimax-h3/plugin.js`

**Step 1: 写失败的请求与 workflow 测试**

在同一个新测试文件中覆盖：

- 合法纯文本请求可解码；空 prompt、非 768p、非白名单比例、5–15 秒外、非整数秒均拒绝。
- 第一阶段拒绝 `metadata.content` 中的参考素材。
- 比例映射为：16:9=`1344x768`、9:16=`768x1344`、1:1=`768x768`、4:3=`1024x768`、3:4=`768x1024`。
- 帧数公式为 `max(5, round(seconds*24))` 后向上对齐到 `17n+5`。
- 相同 `publicTaskId` 生成稳定 seed，不同任务生成不同 seed。
- 静音 workflow 不包含音频 VAE/解码节点和 `CreateVideo.audio`；有声 workflow 包含它们。
- workflow 使用当前机器已验证的 base UNET、CLIP、video/audio VAE，20 steps，不携带未启用的 Turbo LoRA 分支。

- 查询请求为 `GET /history/{prompt_id}`。
- 空 history 为 `IN_PROGRESS`；completed success 且含视频输出为 `SUCCESS`；error/interrupted 或成功但无视频为 `FAILURE`；未知结构为 `UNKNOWN`。
