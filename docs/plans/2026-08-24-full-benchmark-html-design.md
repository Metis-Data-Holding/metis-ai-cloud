# Serving Benchmark 完整 HTML 报告设计

## 目标

将 `reports/demo/benchmark-report.md` 重写为面向老板阅读的完整可视化 HTML：先用一屏摘要回答“业务是否打通、当前能承载多少、瓶颈在哪里、下一步做什么”，再按 Markdown 的 11 个章节提供可核对的完整正文。HTML 不新增未经报告支持的结论，也不把短时探索性测试扩大为生产 SLA。

## 模板选择

采用 Lieflat Charts R09「Data Story Dashboard / 青瓷峰会」作为整页骨架，并保留其 Porcelain 单色体系、刊头、宽版内容区、KPI 摘要、细规线分节与报告页脚。

候选比较：

- R09：摘要区与模块化长正文兼容，适合“老板先看结论、技术人员继续下钻”，选用。
- R04：纵向时间脊柱适合月报事件序列，但会压缩长表格和移动端正文宽度，不选。
- R01：适合问卷式单页，文本承载足够但执行摘要与多阶段测试故事线不够突出，不选。

## 信息架构

1. 老板摘要：业务闭环、稳定并发、槽位实验、GPU、DeepSeek 成本、加权路由。
2. 架构与环境：公网调用路径及硬件、模型、推理参数。
3. 方法与指标：测试边界，以及 TTFT、ITL、端到端延迟、吞吐、分位数的通俗解释。
4. Gemma 容量阶梯。
5. Max Concurrent Predictions 4→6 参数实验及 GPU 资源。
6. 并发 4 的 30 分钟稳定性验证。
7. Gemma 与 DeepSeek 的并发 1 体验参考。
8. DeepSeek 用量、计费与 thinking 成本风险。
9. 同一公开模型名下的 70/30 加权路由与模型映射。
10. 瓶颈判断与明确的证据边界。
11. Demo 与商业化建议。

## 图表映射与候选审计

全页最多使用 5 张数据图，均复用 Lieflat gallery 的真实图形实现；图外另设精确数值与结论，避免图形和数字争夺同一空间。

| 叙事任务 | 采用模板 | 未采用候选及原因 |
|---|---|---|
| 容量阶梯 TTFT 与端到端延迟 | Basics F6 Paired Rungs | F12 更适合单次前后变化；L2 对双指标长标签不够清晰 |
| 容量阶梯聚合吞吐 | Basics F1 Rung Bars | F5 更适合多类目明细；G3 非必要，Basics 已能准确表达 |
| Gemma / DeepSeek ITL | Basics F5 Tick Rows | F1 会弱化“每一格代表固定毫秒”的单位感；L2 对两项比较过重 |
| 20 次非流式路由分布 | Basics F4 Tick Donut | L14 更适合百分位百点场；G4 非必要，Basics 已有正本 |
| 单次 thinking 请求费用占比 | Lupi L14 Hundred Field | F4 会与路由占比重复；L15 适合互不相加的多选项 |

全局只使用 R09 的 Porcelain 色板：深蓝为结论与主数据，中蓝为对照数据，浅蓝为背景单位，暖白为页面底色。

## 防遮挡与响应式规则

- 图形、图例、精确数值、结论分别使用独立 DOM 区域；SVG 内只保留短轴标与几何图形。
- 大数字和模型全名不放进 SVG，不使用绝对定位覆盖图形。
- 卡片采用自然高度，不设置固定 `max-height`；长文本允许正常换行。
- 宽表格包裹在横向滚动容器中；移动端双栏、三栏自动变为单栏。
- 章节和图表卡使用 `break-inside: avoid` 的打印策略，但不强制整页固定高度。
- 动画仅用于首次轻量呈现，并支持 `prefers-reduced-motion`。

## 验收标准

- HTML 明确覆盖 Markdown 的 11 个一级章节及其关键数字、限定语和建议。
- 老板在首屏即可读到项目闭环、稳定并发、主要瓶颈、路由结果和成本风险。
- 不再出现路由点阵与 `13 · 65%` 等精确值相互覆盖的问题。
- 桌面、窄屏和打印布局均保持可读；表格不挤压正文。
- JavaScript 语法、HTML 章节锚点、关键证据值、Secret 扫描和 Git diff 检查通过。
