# 任务日志模型展示与参考内容清理设计

## 背景

异步任务日志当前在任务 ID 下方展示“平台 · 动作”。部分视频任务没有可识别的动作值，因而显示为“doubao · 未知”，虽然任务属性已经保存了请求模型和上游模型。系统任务列表中的 `video_reference_cleanup` 也尚未配置本地化名称、执行进度和结果摘要。

## 目标

- 为模型元数据增加独立、可选的展示名称，不改变 API 模型 ID、计费标识或上游请求模型。
- 在异步任务创建时保存展示名称快照；任务日志优先展示快照，旧任务回退到请求模型 ID。
- 将 `video_reference_cleanup` 的界面名称改为“参考内容清理”，保留内部任务类型不变。
- 清理任务按扫描文件数记录真实进度，并在详情中展示扫描、删除、失败数量及释放空间。

## 模型名称语义

- `origin_model_name` 是客户端请求 New API 时使用的公开模型 ID，并用于计费和渠道选择。
- `upstream_model_name` 是模型映射后实际发送给 Provider 的模型 ID。
- 新增 `display_name` 仅用于界面展示，可在模型管理页配置；未配置时回退到 `origin_model_name`。
- 任务属性增加 `display_model_name` 快照，避免模型展示名称后来变化时改写历史任务的展示语义。

## 数据流

1. 管理员在模型管理页设置可选的 `display_name`。
2. 异步任务初始化时，按 `origin_model_name` 解析当前展示名称并写入任务属性。
3. 任务日志列表显示“平台 · 展示名称”；没有快照的旧任务显示“平台 · origin_model_name”，最后才回退到任务动作。
4. 清理任务读取参考视频临时目录后，以目录项总数为总量，每处理一项上报一次进度；最终结果继续写入 `result`。
5. 系统任务页面将清理结果格式化为可读详情。

## 参考图片边界

当前参考图片在浏览器中转换为 Data URL，并随生成请求发送，不会写入参考视频临时目录。因此本次定时任务仍只删除临时参考视频文件。页面使用较宽泛的“参考内容清理”名称，但详情明确采用“参考视频文件”口径。

## 兼容性与回退

- `display_name` 为可选字段，数据库迁移对现有记录无破坏。
- 旧任务缺少 `display_model_name` 时仍能展示 `origin_model_name`。
- 清理服务的进度回调为可选参数，不改变既有清理结果和 TTL 规则。
- 内部任务类型保持 `video_reference_cleanup`，不影响已有任务记录和调度去重。

- 前端单元测试覆盖任务日志模型名回退和清理任务详情格式化。
