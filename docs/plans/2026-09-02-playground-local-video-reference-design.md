# Playground 本地参考视频设计

## 目标

为 Playground 的“参考生成”模式增加本地视频上传，同时保留现有公网 URL 和 `asset://` 素材 ID。上传的视频临时保存在 ECS，通过限时签名 URL 提供给 BytePlus Seedance 读取。

## 范围

- 支持 MP4、MOV。
- 单个文件不超过 80 MB。
- 本地视频、公网 URL、`asset://` 素材 ID 合计最多 3 个。
- 前端读取媒体元数据，校验单段时长 2～15 秒、所有参考视频总时长不超过 15 秒。
- 后端校验文件大小、媒体类型和文件签名；媒体时长仍以上游校验为最终依据，避免新增 FFmpeg 运行依赖。
- 不接入 TOS、LAS 素材库或新的对象存储。

## 数据流

1. 用户在 Playground 选择本地视频。
2. 前端完成格式、大小和时长预检，然后通过 Dashboard Session 向专用上传接口发送单个文件。
3. 后端将请求体流式写入 `/data/video-reference-uploads/` 下的 `.uploading` 临时文件，校验成功后原子重命名为随机 ID 对应的正式文件。
4. 后端返回文件 ID、显示所需元数据和限时读取 URL。
5. Playground 将读取 URL 作为 `reference_video` 放入现有 Seedance `content` 请求，不改变 Doubao 插件的参考素材协议。
6. BytePlus 通过签名 URL 读取视频并异步执行任务。

## API 与访问控制

- 上传接口仅接受已登录的 Dashboard Session，不接受普通 API Access Token。
- 每次请求只上传一个文件，后端在读取过程中强制 80 MB 上限，不依赖 `Content-Length`。
- 文件名由服务端生成，不使用用户文件名作为路径。
- 内容接口只支持 `GET` 和 `HEAD`，路径包含随机文件 ID；查询参数包含过期时间和绑定文件 ID 的 HMAC 签名。
- 内容接口拒绝过期、签名错误、格式错误和不存在的文件；响应设置明确的媒体类型、长度、Range 支持和 `Cache-Control: private, no-store`。
- Bucket 式目录不提供目录浏览，也不跟随软链接。

## 生命周期与清理

- 保持 BytePlus 默认 48 小时任务执行超时，不为了本地存储缩短上游窗口。
- 正式文件与签名 URL 保留 50 小时，为上游执行窗口保留 2 小时缓冲。
- `.uploading` 文件超过 1 小时视为中断上传。
- 新增 `video_reference_cleanup` 定时系统任务，每小时扫描一次；系统任务框架通过数据库任务记录和租约避免多个 Master 重复执行。
- 应用启动后调度器会安排首次扫描，覆盖停机期间的残留文件。
- 清理只处理指定目录内符合命名规则的普通文件。单文件失败不阻断其他文件，并记录扫描数、删除数、释放字节数和失败数。

## 前端交互

- 在现有参考视频区域增加本地上传入口，不重做整体布局。
- 上传期间显示进度/忙碌状态并禁止重复提交；成功后以现有参考素材卡片展示文件名、大小和时长，可移除。
- 公网 URL、`asset://` 和本地上传共享 3 个视频名额。
- 切换到首尾帧模式时清空参考视频表单状态；已上传的服务器文件由 TTL 清理，不新增即时删除接口。
- 错误文案接入现有 i18n，覆盖格式、大小、时长、总时长、上传失败和名额不足。

## 故障与安全边界

- 上传失败时删除本次 `.uploading` 文件。
- 前端校验只改善体验，后端校验是安全边界；视频内部编码和真实时长由 BytePlus 最终校验。
- 第一版不建立“上传文件—生成任务”数据库关联，也不在任务终态提前删除文件。
- 当前 ECS 是单节点持久化目录；若未来扩展为多应用节点，应迁移到 TOS/S3 等共享对象存储。
- 部署需要确保 `/data/video-reference-uploads/` 可写，并持续监控 ECS 剩余空间。

## 验证

- 后端：上传大小与格式、流式落盘、原子重命名、签名签发/校验、GET/HEAD/Range、过期访问和清理任务测试。
- 前端：选择有效视频、80 MB 边界、格式/时长/总时长限制、上传状态、混合引用上限、删除与模式切换测试。
- 回归：现有公网 URL、`asset://`、参考图片、首尾帧、文生视频和计费请求结构保持不变。
- 部署后：真实上传一个本地参考视频，完成提交、轮询、计费、预览和下载验收，再确认过期内容不可访问。
