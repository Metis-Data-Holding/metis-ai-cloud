# 异步任务使用日志展示设计

## 目标

让通用使用日志正确表达异步视频任务的计费阶段，并仅在任务完成后显示上游返回的实际计费 Token。任务耗时继续以任务日志为准，本次不调整通用日志的耗时列。

## 方案

异步任务提交日志继续作为不可变的计费审计记录，不直接更新 `logs.prompt_tokens` 或 `logs.completion_tokens`。原因是日志库可能独立使用 ClickHouse，且视频计费 Token 允许小数，现有整数字段不能无损承载。

任务成功完成并完成表达式结算时，将最终 `UsageFacts` 与“已结算”标记写回任务的计费快照。查询使用日志时，后端按页面内的 `task_id` 批量查询任务，并仅对已结算成功任务在日志响应的 `other` 中补充 `task_usage_tokens`。该补充只影响 API 展示响应，不改写历史日志和费用统计。

前端根据日志结构显示计费阶段：

- 异步任务首次消费日志显示“预扣”；
- 带 `pre_consumed_quota` 与 `actual_quota` 的正向差额日志显示“补扣”；
- `LogTypeRefund` 继续显示“退款”；
- 其他同步消费日志继续显示“消耗”。

Token 列在任务未结算时显示 `-`；结算后显示 `task_usage_tokens` 单值，不伪装成文本模型的输入/输出 Token。通用日志耗时列保持现状，准确的任务总耗时仍在任务日志读取 `submit_time` 与 `finish_time`。

## 兼容性与错误处理

- 任务用量补充采用一次批量查询，不为每行单独请求。
- 旧任务没有“已结算”标记时保持原显示，不把提交阶段估算值误当成实际值。
- 任务查询或快照解析失败时保留原日志，不影响日志页面主体数据。
- 不改变现有日志类型、费用字段、统计 SQL、退款逻辑和任务耗时口径。

## 验证

- 后端测试覆盖：完成结算后快照持久化、未完成不暴露 Token、已完成日志响应补充小数 Token。
- 前端测试覆盖：预扣、补扣、退款标签与完成前后 Token 展示。
- 运行相关 Go 测试、前端定向测试、类型检查、Lint、格式检查和构建。
