# Playground 模型显示名称设计

## 目标

Playground 的模型选择器优先展示管理员配置的模型显示名称，同时保留模型 ID 供识别、搜索和排障；实际提交给 API 的模型值仍为模型 ID。

## 方案

保留 `/api/user/models` 现有 `data: string[]` 响应，避免破坏既有客户端；在响应顶层新增按模型 ID 索引的 `model_display_names` 映射。前端将模型 ID 保存在 `value`，将非空显示名称作为 `label`，并把模型 ID保存在可选的 `description` 字段。

选择器触发按钮只显示 `label`。展开列表时以 `label` 为主标题；当 `label` 与 `value` 不同时，在下一行显示模型 ID。搜索覆盖显示名称、模型 ID 和既有描述字段。显示名称缺失或空白时回退到模型 ID，不显示重复的次级文本。

## 数据与兼容边界

- 模型可用范围仍由用户分组、渠道能力和端点类型决定。
- 显示名称只来自已配置模型元数据，不改变渠道路由、计费、模型映射或上游请求。
- 旧客户端继续读取 `data`，行为不变；新前端读取可选映射，兼容旧后端。
- 管理员修改显示名称后，下一次模型列表请求即可得到新名称。

## 验证

- Go 控制器测试：响应继续返回字符串数组，并只为非空显示名称提供映射。
- 前端 API 测试：有显示名称时生成双字段选项；无映射、空白名称和旧响应时回退。
- 组件测试：列表显示主名称和次级 ID，触发器只显示主名称，搜索 ID 仍可找到选项。
