# Design Context

## Users

The primary users are developers, technical evaluators, and enterprise demo participants who use Playground to test model capabilities, inspect asynchronous task behavior, and validate media output before integrating the API. They need fast configuration, clear task feedback, and predictable controls more than a consumer-style creative editor.

## Brand Personality

Precise, restrained, capable, and trustworthy. The interface should feel like a focused technical workspace: polished enough for demos, but never decorative at the expense of clarity.

## Aesthetic Direction

Use the existing New API visual language, semantic theme tokens, typography, and component primitives. Borrow BytePlus ModelArk's interaction hierarchy—one unified composer with progressive disclosure—but do not copy its branding. Prefer a compact bordered surface, subtle elevation, generous prompt space, and quiet controls. Avoid gradients, nested cards, raw colors, and ornamental animation. Preserve both light and dark themes.

## Design Principles

1. Keep creation in one place: references, prompt, mode, parameters, model, and submit belong to one composer.
2. Reveal complexity on demand: show a concise parameter summary by default and expose controls in a popover or mobile sheet.
3. Preserve operational truth: every requested output is an independent asynchronous task with its own status, error, preview, and download action.
4. Stay responsive and accessible: controls wrap instead of overflowing, touch targets remain usable, overlays escape scroll containers, and icon-only actions have explicit accessible names.
5. Minimize upstream divergence: reuse current API, upload, billing, task polling, and shared UI seams; add no provider-specific schema or dependency.
